feat(v13-dx): add SimbaPlayer wrapper + resolveStreamType helper

V13 DX additions for @simba-dev/react-native-media-player.
Both are designed to make the consumer-side integration as simple
as possible (the user-defined goal: "junior-dev level").

resolveStreamType (useOpenWithResume.tsx):
  - Maps consumer content kinds ('music', 'movie', 'podcast',
    'live-tv', 'radio', 'audiobook', 'archive-audio',
    'episode', 'video-file') to V13 stream types
    ('audio' | 'video').
  - Passthrough for already-V13 stream types ('video' | 'audio').
  - Idempotent: double-wrapping is safe.
  - Exported as `resolveStreamType` + the `ContentKind` type.
  - Used in the 32 V13 screen-file migrations to absorb the
    content-kind -> stream-kind mapping that would otherwise be
    an inline ternary in every file.

SimbaPlayer (new file: src/hooks/SimbaPlayer.tsx):
  - The one-import, one-wrapper integration point for the
    module. Composes PlayerProvider + PlayerResumeProvider
    under a single component.
  - Props: `config?: PlayerConfig`, `lookup?: PlayerResumeLookup`,
    `children`.
  - Junior-dev App.tsx integration:
    ```tsx
    import { SimbaPlayer } from '@simba-dev/react-native-media-player';
    <SimbaPlayer lookup={myBookmarkLookup}>
      <RootNavigator />
    </SimbaPlayer>
    ```
  - The `lookup` is optional; if omitted, the inner
    PlayerResumeProvider is mounted with a no-op lookup that
    always returns undefined. Screens that pass `resumeId` in
    their openPlayer call get auto-resume; screens that don't are
    unaffected.
  - Exported from index.ts as `SimbaPlayer` + `SimbaPlayerProps`.

Together with the previously-committed useOpenWithResume /
PlayerResumeProvider / usePlayItem (commit 696fef9), the module
now provides a complete public surface for the V13 migration:

  - SimbaPlayer (the wrapper)
  - usePlayerActivity (raw openPlayer access)
  - useOpenWithResume (auto-resume)
  - usePlayItem (one-line press handler)
  - PlayerRoot + DefaultControls (the V13 UI, Phase 54)
  - getMpvPlayerModule() (the typed bridge)
  - resolveStreamType (content-kind -> stream-kind helper)
